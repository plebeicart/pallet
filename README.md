# Паллетная Компания

Готовый статический корпоративный сайт на HTML5, CSS3 и Vanilla JavaScript. Сборка, Node.js и npm для запуска не нужны. Работа выполнена в текущем каталоге, без публикации во внешнем хостинге.

## Запуск на Ubuntu

Из каталога проекта:

```bash
python3 -m http.server 8080
```

Откройте http://localhost:8080. Остановка сервера: Ctrl+C. Если Python отсутствует: `sudo apt install python3`.

## Файлы

- `index.html` — главная, каталог из шести позиций, услуги, производство, компания, этапы, заявка и контакты.
- `css/style.css` — визуальная система, адаптивность 320–2560+, состояния, reduced motion.
- `js/main.js` — мобильное меню, фильтры, модальные окна, валидация и адаптер отправки.
- `privacy.html` — честное описание обработки данных демонстрационной версии.
- `assets/images/` — локальные фотографии исходного сайта.
- `assets/icons/favicon.svg` — новая монограмма ПК; остальные SVG встроены в HTML.
- `assets/fonts/` — Manrope с кириллицей, веса 400, 700, 800 и лицензия OFL.
- `qa/` — снимки desktop и mobile; `qa/report.md` — результат проверок.

## Реализовано

Sticky header, мобильное меню с Escape и закрытием по внешнему клику, якорная навигация, пять фильтров каталога, модальные заявки с выбранным товаром, подробности шести дополнительных услуг, native dialog с удержанием фокуса и Escape, кнопка наверх, появление блоков при прокрутке, hover и focus, reduced motion. Телефоны и email кликабельны; адрес открывается в Яндекс Картах.

Формы проверяют имя, телефон (10–15 цифр и допустимые символы), обязательное согласие. Никакие данные в текущем режиме не отправляются и не хранятся. Уведомления выводятся через live region. Backend и внешняя аналитика не подключены.

## Подключение заявок

В `js/main.js` задана константа `FORM_ENDPOINT = ''`. После подготовки сервера задайте свой same-origin путь, например `/api/leads`.

Клиент отправляет JSON через POST: `name`, `phone`, `subject`, `consent` (`on`), а в расширенной форме ещё `message`. Успех подтверждается только HTTP 2xx и JSON `{"ok":true}`. Другой статус, невалидный JSON или сетевая ошибка показывают сообщение об ошибке. Кнопка блокируется на время запроса. При настроенном endpoint демонстрационные уведомления скрываются, кнопки меняются на «Отправить заявку».

Сервер должен отклонять заявку без явного согласия: принимать только `consent: "on"`, при отсутствующем или ином значении возвращать HTTP 400 без сохранения и пересылки заявки. Проверка на клиенте не заменяет эту серверную проверку. Сервер должен повторно валидировать поля, ограничивать частоту запросов, защищаться от спама, контролировать допустимый Origin, безопасно хранить/пересылать обращения и возвращать правильный статус. Политика размещена в `privacy.html`, отдельное согласие — в `consent.html`; тексты перенесены из `Untitled 1.docx`. Перед включением приёма проверить актуальность документов и реализовать серверную проверку согласия. Не включать endpoint до готовности сервера и документов.
