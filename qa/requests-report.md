## Аудит и пределы проверки

- `REQUESTS_ENABLED=false` — значение по умолчанию и в шаблоне. Пока выключено,
  браузер не отправляет поля, backend отвечает 503 до чтения тела.
  Существующее обязательное согласие сохранено и проверяется сервером.
- В коде нет SMTP-пароля, адресат задан строго в Punycode, пользовательские поля
  не используются как заголовки/адреса письма. В логах только фиксированные коды.
- SMTP блокирует отдельный thread, HTTP event loop остаётся свободен.
  Лимиты/дедупликация ограничены памятью, работает один worker; данные заявок
  не записываются в базу/файлы. После рестарта дедупликация сбрасывается.
- При неоднозначной SMTP-ошибке автоматической повторной отправки нет.
  Exactly-once между рестартами и гарантия доставки во входящие невозможны
  при данном контракте без постоянного хранилища/проверки почтового провайдера.
- Простая антиспам-защита не останавливает распределённую атаку; общий лимит
  может временно ограничить реальных клиентов. Настройки описаны в инструкции.
- systemd запускает только 127.0.0.1:8000, доверяет proxy headers только локальному
  Caddy; в Caddy заголовок X-Forwarded-For перезаписывается адресом соединения.
  Вариант с CDN/ещё одним прокси требует отдельной настройки доверия.
- Caddy-фрагмент отделяет публичные каталоги от служебных файлов и отключает
  access logging API; секрет — `/etc/pallet-api/pallet-api.env`, root:root 0600,
  backend — `/opt/pallet-api`, без прав записи у сервиса.
- **Caddy не установлен в локальной среде**: его реальный validate/reload,
  HTTPS, security group и работа systemd на VPS не проверялись. Локальный
  systemd-analyze распознал unit, но сообщил об ожидаемо отсутствующем
  `/opt/pallet-api/current/.venv/bin/python`; сервис не устанавливался.
  Проверка на VPS включена в обязательные команды перед запуском.
- Браузерные тесты проверяют frontend с mock API; Python-тесты проверяют
  настоящее ASGI-приложение с mock SMTP. Production SMTP/почтовый ящик и
  полная цепочка через настоящий Caddy должны быть проверены вручную только
  после юридического разрешения. SMTP-тест пользователя на VPS не повторялся.

Точные команды локального запуска, подготовки релиза из GitHub, размещения
секрета, backup, установки systemd, правки Caddy, включения и отката:
[`docs/requests-deployment.md`](../docs/requests-deployment.md).

Предыдущие числа проверок относятся к исходной реализации. Актуальные результаты
и таблица исправлений находятся в `qa/astra-remediation.md`. Инструкция изменена:
