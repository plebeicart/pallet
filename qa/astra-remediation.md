# Исправления после аудита Astra

Отчёт Astra из контекста сверён с текущим кодом. Никаких production-действий,
SSH, DNS, push, настоящих SMTP-паролей или отправок писем не выполнялось.
REQUESTS_ENABLED по умолчанию остаётся false. Визуальный CSS, контакты,
анимации и действия вне форм не изменены.

## Результаты

- 64 Python-теста прошли (52 исходных сценария с обновлёнными ожиданиями и
  12 новых параметризованных/отдельных проверок).
- 107 браузерных проверок: две формы, отключённый/заблокированный JS, отправка,
  ошибки, сохранение полей, меню, фильтры, все request/service кнопки, 6 ширин.
- node --check js/main.js, git diff --check, git check-ignore .env .env.production.
- pip-audit для requirements-dev.txt, включая runtime: известных уязвимостей нет.
- Во всех Python API-тестах SMTP_SSL подменён и socket.create_connection запрещён;
  Playwright использует mock API. Настоящих SMTP-соединений не было.
- В первом прогоне было 6 падений прежних ожиданий: код 502 заменён на 503 для
  определённых отказов, а дубликат теперь возвращает сохранённый успех до проверки
  почтового бюджета. Ожидания скорректированы и проверены новыми регрессиями.
- При усилении browser-теста обнаружено ошибочное ожидание: тест сам снимал
  disabled при полностью выключенном JS. Native POST после такой модификации
  ожидаем. Тест исправлен: в no-JS проверяет штатный Enter с disabled, в blocked-JS
  дополнительно проверяет inline отмену принудительного submit с валидными полями.
- Осталось предупреждение Starlette о рекомендуемом переходе с httpx на httpx2;
  текущие закреплённые версии проходят тесты. Предупреждение не скрыто.

## Конфигурация и проверка на VPS

Caddy в локальной среде отсутствует. Сохранён handle /api/* без удаления префикса,
перезапись X-Forwarded-For адресом соединения, max_size 16KB, upstream 127.0.0.1:8000.
Добавлен deploy/Caddy-global.fragment для read_header/read_body тайм-аутов; его
нужно объединить с существующим глобальным блоком, не вставлять в блок сайта.
Caddy validate и actual reload локально не выполнялись. Не заявляется, что шаблон
проверен на установленной на VPS версии.

systemd уже имел отдельного пользователя, loopback, единственный worker,
forwarded-allow-ips=127.0.0.1, ProtectSystem=strict, запрет core dump и access log.
Подтверждённого дефекта этих параметров не обнаружено; unit не переписывался.
Пароль остаётся в /etc/pallet-api/pallet-api.env root:root 0600 (каталог 0700).
Инструкция теперь устанавливает в runtime только requirements.txt; QA-окружение
отдельно. Права релиза явно u=rwX,g=rX,o=, без записи для группы сервиса.

На VPS вручную проверить: версию и validate Caddy с существующими imports/TLS,
закрытие служебных URL, размер и медленное тело запроса, реальную передачу IP
с поддельными заголовками, bind только 127.0.0.1, права секрета/релиза, старт и
рестарт systemd, восстановление из backup под обычным администратором через sudo.
Репетировать откат сначала на стенде. После юридического подтверждения — одна
согласованная контрольная заявка и проверка корпоративного ящика.
